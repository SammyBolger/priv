# Patterns Defined

A pattern is a repeatable solution, code, or practice that can be easily applied to a solution.

## Purpose and Scope

- The value of the pattern is **speed to execution** - leveraging what others have done before and quickly achieving business outcomes
- A pattern is best expressed as **When to use / When Not to use** certain technologies or approaches
- This content is a distillation of many successful implementations
- If implemented properly, these patterns enable you to get to production as fast as possible and have the most stable, scalable, and maintenance-free set of applications possible

## Pattern of Patterns - TEMPLATE

Use the following structure for defining patterns:

### Pattern Subject Area Overview

- Provide an overview and definition of the pattern
- Example: This describes strategies (in the form of patterns) for common integration scenarios. Each pattern describes the design and approach for a particular scenario rather than a specific implementation.

### Name

- The pattern identifier that also indicates the type of integration or architecture concern contained in the pattern.

### Context

- The overall scenario that the pattern addresses. Context provides information about what users are trying to accomplish and how the application will behave to support the requirements.

### Problem

- The scenario or problem (expressed as a question) that the pattern is designed to solve. When reviewing the patterns, read this section to quickly understand if the pattern is appropriate for your scenario.

### Solution

- The recommended way to solve the scenario.
- Include items that should **not** be considered

### Sketch

- A UML sequence diagram or architecture diagram that shows how the solution addresses the scenario.

### Results

- Explains the details of how to apply the solution to your scenario and how it resolves the associated forces. This section also contains new challenges that can arise as a result of applying the pattern.

### Sidebars / Related Sections

- Additional sections related to the pattern that contain key technical issues, variations of the pattern, pattern-specific concerns, and so on.
